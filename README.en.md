# 🧞 minions — Personal One-Shot, End-to-End Coding Agents

**[日本語](README.md)** | English

A personal-scale, **unattended one-shot coding agent** platform built on [goose](https://github.com/block/goose),
inspired by [Stripe's Minions blog series](https://stripe.dev/blog/minions-stripes-one-shot-end-to-end-coding-agents)
([Part 2](https://stripe.dev/blog/minions-stripes-one-shot-end-to-end-coding-agents-part-2)).

Give it a task and it runs **isolated in a worktree → goose implements → lint/test auto-fix → commit → push → CI (max 2 rounds) → PR creation** — no human interaction required.

## 🤖 What is minions? — For first-time readers

### In one sentence

**minions is a personal AI coding minion: hand it a task, and it keeps going until a PR is ready.**

```bash
minion run "Add rate limiting to the login API, with tests"
```

With this single command, minions does all of the following **unattended**:

1. Creates an **isolated workspace (git worktree)** so your repo stays untouched
2. Has an AI agent (goose) read your rule files and implement the code
3. Runs lint auto-fix and tests; on failure, the AI investigates and self-repairs
4. commit → push → CI (max 2 rounds; the AI fixes failures and retries) → **creates the PR automatically**

The only human step is the final **PR review**. The workflow is: "throw a task in, review the finished PR."

### Why it exists (problems it solves)

Using a coding agent directly tends to hit these issues:

| Problem | minions' answer |
|---|---|
| The agent dirties your working branch | **1 task = 1 worktree** — fully isolated; parallel tasks are safe |
| It stops mid-task to ask questions | One-shot, unattended by design; it is told not to ask and runs to completion |
| Humans keep fixing lint/test/CI failures | Deterministic nodes auto-fix; failure logs are fed back for AI self-repair |
| Letting an LLM do git ops causes accidents | commit / push / PR are done by **deterministic code, no LLM involved** |
| Rule files differ per tool | A single `AGENTS.md` shared by goose / Claude Code / Cursor |

The design philosophy is a personal-scale port of [Stripe's Minions](https://stripe.dev/blog/minions-stripes-one-shot-end-to-end-coding-agents):
**"make every determinable decision deterministically in code; give the agent only what needs creativity."**

### What it can and cannot do

- ✅ Take clearly-specified tasks (features, refactors, bug fixes, tests) and deliver a PR
- ✅ Run multiple tasks in parallel while you focus on reviewing
- ❌ Pair programming with back-and-forth dialogue (unattended: it cannot ask you questions)
- ❌ Act as a git proxy (the agent is forbidden from commit/push; the orchestrator does it deterministically)

### Key concepts (glossary)

| Term | Meaning |
|---|---|
| **minion** | One execution of a one-shot agent that completes a single task; one is spawned per `minion run` |
| **minions** | This repository/tool: the platform that launches, isolates, and supervises minions (the Blueprint) |
| **one-shot** | Running from task start to completion in a single pass, without human intervention |
| **worktree** | A git feature providing an independent workspace of the same repo; 1 task = 1 worktree, so tasks never interfere |
| **Blueprint** | The state machine driving a task: a mix of "deterministic nodes" and "AGENT nodes" |
| **Deterministic node** | A step that uses no LLM and always behaves identically (worktree setup, lint, commit, push, PR) |
| **AGENT node** | A step where goose has latitude (implementation; diagnosing and fixing test/CI failures) |
| **run** | A single minion execution; logs, state, and artifacts live in `~/.minion/runs/<run_id>/` |
| **AGENTS.md** | The project rule file agents must follow; generated by `minion init` |
| **`.minion.yaml`** | Per-repository config (lint/test/CI commands, PR base, etc.) |

## Architecture (Stripe Minions → personal edition)

| Stripe concept | This implementation |
|---|---|
| Minion (unattended one-shot agent) | `minion run "task"` |
| Fork of goose (agent core) | **goose 1.46, as-is** (`goose run --no-session`) |
| Blueprint (state machine of deterministic + agent nodes) | state machine in `lib/minions/blueprint.py` |
| Devbox (isolated, parallel dev environment) | **git worktrees** (`~/.minion/worktrees/`) |
| Agent rule files (shared with Cursor/CLAUDE.md) | `AGENTS.md` + `CLAUDE.md` symlink (`minion init`) |
| Conditional rules scoped to subdirectories | hydrate node collects subdirectory `AGENTS.md` files |
| Toolshed (central MCP, curated tools) | goose MCP config + `goose_args` in `.minion.yaml` |
| Shift-left feedback (local lint → max 2 CI rounds) | lint auto-fix ≤3 loops → tests → agent fix ≤2 → CI ≤2 rounds |

### Why we don't fork goose (biggest divergence from Stripe)

Stripe forked goose internally in late 2024 and modified the agent loop itself
(integration with their LLM infrastructure, unattended runs without permission prompts,
and interleaving agent loops with deterministic code).
This project deliberately does **not fork goose** — it invokes goose as a subprocess via its CLI:

| What Stripe achieved with a fork | How the personal edition achieves it |
|---|---|
| Integration with internal LLM infra | goose provider configuration (fully local) |
| Unattended runs (no interactive prompts) | `goose run --no-session` + `GOOSE_MODE=auto` |
| Interleaving agent loop with deterministic code | **Blueprint lives outside goose (Python)**; only AGENT nodes call `goose run` |
| Toolshed (curated internal tools) | goose MCP + `goose_args` in `.minion.yaml` |
| Devboxes (isolated, parallel envs) | git worktrees (Stripe notes worktrees "wouldn't scale at Stripe" — fine at personal scale) |

Stripe embeds orchestration *inside* the agent runtime; this project uses the agent *inside* the orchestrator.
That lets the state machine evolve freely without touching the agent core, and lets you track
upstream goose releases and extension mechanisms (MCP, recipes) as-is.

A fork carries permanent costs — tracking upstream, security patches, build & distribution — and is only
justified **when you need to change the agent loop itself**. Extensions here follow the ladder
`CLI flags → MCP/recipes → upstream PR`, with forking as the last resort.

## Blueprint (state machine)

```
setup ── hydrate ──▶ implement ──▶ lint(auto-fix ≤3) ──▶ test ──┐
(det.)   (det.)      (AGENT)        (det.)              (det.)  │ fail
                                                                  ▼
done ◀─ pr ◀─ ci(≤2 rounds) ◀─ push ◀─ commit ◀── tests pass ◀── fix_tests (AGENT)
       (det.)  ▲                                      (det.)            │ fail
               │             fix_ci (AGENT) ◀────── CI failed ◀────────┘
```

- **AGENT nodes**: goose gets broad latitude (implementation, failure repair)
- **Deterministic nodes**: git ops, lint, tests, push, PR never touch an LLM
  → Stripe's lesson: "Determinable, small decisions are best made deterministically in code" —
  saving tokens and CI while shrinking the space where the agent can go wrong.

## Setup

Prerequisites: [goose](https://github.com/block/goose) / git / python3 (3.9+). For automatic PR creation, [gh](https://cli.github.com/) is optional (`gh auth login` required).

```bash
git clone https://github.com/takezou621/minions.git
mkdir -p ~/.local/bin
ln -sf "$(pwd)/minions/bin/minion" ~/.local/bin/minion
export PATH="$HOME/.local/bin:$PATH"   # add to ~/.zshrc etc. to make it permanent
minion doctor   # verify dependencies and PATH
```

## Usage

### 1. Initialize a target repository (once)

```bash
cd ~/dev/your-repo
minion init
# → generates AGENTS.md (rule file), CLAUDE.md (symlink), .minion.yaml (auto-detected)
#   Write your conventions in AGENTS.md, then COMMIT it
#   (worktrees are created from HEAD)
```

### 2. One-shot run

```bash
minion run "add rate limiting to the login API, with tests"
# Parallelize (the Stripe way: many minions at once)
minion run -d "task A" &
minion run -d "task B" &
minion list
```

### 3. Observe & inspect

```bash
minion list                # all runs
minion log -f              # tail the latest run's transcript
minion show <run_id>       # timeline + status
minion dashboard           # → http://localhost:8765 (Web UI, 5s auto-refresh)
minion clean               # remove worktrees of finished/failed runs
```

### 4. PR

If the remote is GitHub, `gh pr create` runs automatically (base = `pr_base` in `.minion.yaml`).
The PR body is the agent-written `summary.md` (falling back to the last commit log). Humans only review.

## `.minion.yaml` reference

```yaml
lint:
  fix: ["ruff check --fix .", "ruff format ."]  # auto-fixes run by the deterministic node
  check: ["ruff check ."]                        # check-only lints
test: "python3 -m pytest -q"                     # local tests
ci: "python3 -m pytest -q"                       # CI-equivalent local run (falls back to test; if both unset, watches GitHub Actions)
pr_base: "main"                                  # PR base branch
goose_args: ["--with-builtin", "developer"]      # extra args for goose (curate the "smaller box")
```

## Rule files (Stripe's context engineering)

- The root `AGENTS.md` is read **unconditionally** → keep it minimal
- Put detailed conventions in **subdirectory `AGENTS.md` files** (e.g. `services/api/AGENTS.md`)
  → the hydrate node collects them (`.cursorrules` too) and marks them "READ FIRST" in the implementation prompt
- `CLAUDE.md` is a symlink, so goose / Claude Code / (if synced) Cursor all share **the same rules**

## MCP (Toolshed equivalent)

Uses goose's MCP support as-is:

```bash
goose configure   # add MCP servers (GitHub, Linear, Notion, ...)
```

`goose_args` in `.minion.yaml` can also restrict tools per run
(Stripe's lesson: "agents work best with a curated, smaller box of tools").

## Repository layout

```
repository root (wherever you cloned)/
├── bin/minion              # CLI entry
├── lib/minions/
│   ├── core.py             # run state, config detection, git helpers
│   ├── blueprint.py        # state machine (deterministic/AGENT nodes)
│   ├── cli.py              # init/run/list/log/show/clean/doctor
│   └── dashboard.py        # local Web UI
├── templates/AGENTS.md     # rule file template
└── README.md
~/.minion/
├── runs/<run_id>/          # status.json, transcript.log, summary.md, changes.patch
└── worktrees/<repo>-<id>/  # isolated workspace (1 task = 1 worktree)
```

## Use-case quick reference

Expected use cases derived from the documented features.

| Category | Use case | Key (command / setting) |
|---|---|---|
| **Task execution** | Feature + tests completed one-shot | `minion run "task"` → all the way to a PR, unattended |
| | Refactors / bug fixes / test additions run the same flow | Same command, different task text |
| | Self-healing: lint auto-fix ≤3 loops; test/CI failures fixed by the agent ≤2 times from failure logs | Blueprint round limits |
| **Run modes** | Foreground run, success/failure via exit code | `minion run` (exit 0/1) |
| | Parallel runs while you focus on reviews | `minion run -d "task" &` × N (1 task = 1 worktree) |
| | Use across multiple repositories | `minion init` per target repo |
| **Monitoring** | Track in-flight / finished runs | `minion list` / `log -f` / `show <run_id>` |
| | Monitor parallel runs in a Web UI | `minion dashboard` (:8765, 5s auto-refresh) |
| | Audit artifacts | `summary.md` / `changes.patch` / `transcript.log` under `~/.minion/runs/<id>/` |
| **Receiving PRs** | PR body is the agent-written summary | `summary.md` → `gh pr create` body |
| | Target different base branches | `pr_base` in `.minion.yaml` |
| **Environment variations** | No `gh` / non-GitHub origin → push only, PR skipped | gh is optional |
| | No origin remote → completes locally (writes `changes.patch` too) | event "completed locally (no remote)" |
| **On failure** | Unrecoverable test/CI failure → run fails; inspect logs to find the cause | fix ≤2 / CI ≤2 rounds |
| | Implement agent fails → inspect transcript, refine the task text, re-run | `minion log` |
| **Config & rules** | Auto-detect lint/test commands per language | `minion init` (pyproject / package.json / Cargo.toml / go.mod / Makefile) |
| | Incremental adoption — unset lint/test nodes are skipped | `.minion.yaml` defaults |
| | Minimize / extend tools available to the agent | `goose_args` (smaller box) / `goose configure` (MCP) |
| | Inject subdirectory conventions into the implementation prompt | sub `AGENTS.md` / `.cursorrules` → hydrate node |
| | Share conventions across tools | `CLAUDE.md` symlink |
| **Maintenance** | Diagnose dependencies & provider | `minion doctor` |
| | Clean up worktrees of finished/failed runs | `minion clean` |

Out of scope (anti-use cases): interactive pair programming; acting as a git proxy (agents may not commit/push — the orchestrator does so deterministically).
